# 安全性分析：ECDH-PSI 隐私求交协议

本文档给出本系统所采用协议的形式化描述、安全模型、安全性证明梗概与泄露分析。

## 1. 协议描述

**公共参数**：Ristretto255 群 $\mathbb{G}$（素数阶 $\ell \approx 2^{252}$，Curve25519 余因子商群，规范编码）；哈希到曲线函数 $H: \{0,1\}^* \to \mathbb{G}$，由 `SHA-512` + `ristretto255_from_hash`（Elligator 2 映射）实例化，在建模中视为**随机预言机**。

**输入**：甲方（银行 A）持有集合 $X=\{x_1,\dots,x_{n_A}\}$，乙方（银行 B）持有集合 $Y=\{y_1,\dots,y_{n_B}\}$（元素为规范化后的账号）。

```
A: 采样 a ← Z_ℓ (会话私钥, 用完销毁)          B: 采样 b ← Z_ℓ
A → B:  U_A = { H(x)^a | x ∈ X }  (随机打乱顺序)
B → A:  U_B = { H(y)^b | y ∈ Y }  (随机打乱顺序),
        V_A = { u^b | u ∈ U_A }   (与收到顺序一致)
A:      计算 V_B = { u^a | u ∈ U_B }
        交集标签 S = { t ∈ V_A } ∩ { t ∈ V_B }
        (因为 H(z)^{ab} = H(z)^{ba}, z ∈ X∩Y 当且仅当其标签出现在两侧)
A → B:  V_B, S
A 输出: { x ∈ X | tag(x) ∈ S }      B 输出: { y ∈ Y | tag(y) ∈ S }
```

正确性：$z \in X \cap Y \iff H(z)^{ab} \in V_A \cap V_B$（忽略 $H$ 的碰撞，随机预言机下碰撞概率 $\le q^2/2^{256}$，可忽略）。

## 2. 安全模型

- **敌手类型**：半诚实（honest-but-curious）——参与方按协议执行，但试图从消息中推断额外信息。银行间有监管与合约约束，这是同业协作场景的标准假设（恶意模型防护见 §6）。
- **计算假设**：Ristretto255 群上的 **DDH（判定性 Diffie-Hellman）假设**——给定 $(g, g^a, g^b)$，$g^{ab}$ 与随机群元素计算不可区分。
- **理想功能** $\mathcal{F}_{\text{PSI}}$：接收 $X$、$Y$，向双方输出 $X \cap Y$ 与 $|X|$、$|Y|$，此外无任何输出。

**定理（梗概）**：在 DDH 假设下、随机预言机模型中，上述协议在半诚实敌手存在时安全地实现 $\mathcal{F}_{\text{PSI}}$。

该协议即 Meadows (1986) 与 Huberman–Franklin–Hogg (1999) 的 DH-PSI，与 Google Private Join and Compute / open-source "private-join-and-compute" 库及 Apple 儿童安全方案中的 PSI 同属一族，属于学术界与工业界最广泛部署的 PSI 构造之一。

## 3. 证明梗概（模拟范式）

需构造模拟器 $\mathcal{S}$，使得任意 PPT 区分者无法区分"真实协议执行中敌手的视图"与"模拟器仅利用理想功能输出产生的视图"。

### 3.1 甲方被腐蚀（A 的视图）

A 的视图为：$\text{view}_A = (X,\ a,\ U_B,\ V_A,\ \text{输出})$。

模拟器 $\mathcal{S}_A$ 仅持有 $(X,\ X\cap Y,\ n_B)$，构造如下：

1. 对 $x \in X$ 如实计算 $H(x)^a$（A 自己发的消息，可自模拟）。
2. 对 $U_B$：采样 $n_B$ 个**随机群元素** $\{R_1,\dots,R_{n_B}\}$ 并打乱。
3. 对 $V_A$：对每个 $x \in X$：
   - 若 $x \in X \cap Y$：从 $\{R_j\}$ 中取一个未使用的元素 $R$，令对应标签为 $R^a$（即把 $R$ "当作" $H(x)^b$）；
   - 若 $x \notin X \cap Y$：输出**独立随机群元素**作为其标签。
4. 把随机预言机 $H$ 的应答按上述承诺编程（program），保持一致性。

**不可区分性**：
- 真实视图中，$y \notin X$ 时 $H(y)$ 对 A 是随机预言机输出（A 不知 $y$，无法查询），故 $(H(y), H(y)^b)$ 在 A 看来是一个 DH 对；由 DDH 假设，$H(y)^b$ 与随机群元素不可区分——因此 $U_B$ 模拟正确。
- $x \notin X\cap Y$ 时，标签 $H(x)^{ab}$ 是"双方私钥的 DH 值"，由 DDH（更精确地，由随机预言机下的 **gap-DH / one-more-DH** 类归约，参见 Huberman–Franklin–Hogg 及后续形式化，如 De Cristofaro–Tsudik 2010）与随机元素不可区分——因此 $V_A$ 模拟正确。
- $x \in X\cap Y$ 时标签必然等于 $H(x)^{ab}$，模拟器用 $R^a$ 重现的分布与真实一致（$R$ 均匀 $\Rightarrow$ $R^a$ 均匀，且与 $U_B$ 中的位置一一对应）。

故 $\text{view}_A \approx_c \mathcal{S}_A(X, X\cap Y, n_B)$：A 除交集与 $|Y|$ 外学不到任何东西。特别地，A 无法对 $Y \setminus X$ 做任何成员测试（见 §5 对"伪装条目"这一功能性泄露的说明）。

### 3.2 乙方被腐蚀（B 的视图）

对称。B 的视图为 $(Y,\ b,\ U_A,\ V_B,\ S,\ \text{输出})$。模拟器 $\mathcal{S}_B$ 用 $(Y,\ X\cap Y,\ n_A)$ 以同样方式模拟 $U_A$（随机群元素，DDH 归约），并按 $X\cap Y$ 编程 $S$ 与 $V_B$ 中对应标签；$y \notin X\cap Y$ 的标签同样由 DDH 与随机不可区分。

### 3.3 被动网络窃听者

窃听者只看到 $\{H(x)^a\}$、$\{H(y)^b\}$、$\{H(z)^{ab}\}$ 等群元素。在随机预言机模型下这些输入点本身不泄露 $x$（原像隐藏），且由 DDH，这些幂值与独立随机群元素不可区分。**即使传输层被完全监听，窃听者也无法恢复任何账号或交集**。但主动中间人可篡改/重放消息，故生产部署仍应使用 TLS + 双向证书认证（见 §6）。

## 4. 泄露分析（精确刻画）

协议执行后，各方**恰好**知道：

| 信息 | A 知道 | B 知道 | 窃听者 |
|---|---|---|---|
| 自己的名单 $X$ / $Y$ | ✓（自己的） | ✓（自己的） | ✗ |
| 对方名单大小 | ✓ ($n_B$) | ✓ ($n_A$) | ✓（流量长度） |
| 交集 $X \cap Y$ | ✓ | ✓ | ✗ |
| 对方交集中条目的**位置/顺序** | ✗（已打乱） | ✗（已打乱） | ✗ |
| 对方名单的**非交集**部分 | ✗ | ✗ | ✗ |

集合大小泄露是 PSI 功能的固有部分（理想功能也输出大小）；如需隐藏可在名单尾部填充随机哑元（padding），本实现未启用。

## 5. 功能性泄露的诚实说明

PSI 功能本身允许一种"查询"：任何一方可以把关心的账号 $z$ 塞进自己的名单，从而检测 $z$ 是否在对方名单中（每次执行最多检测 $n$ 个）。这是**所有** PSI 协议的固有属性，而非本实现的缺陷。治理层面的缓解措施：协议执行次数审计、名单条目数上限、双方会签的执行日志。本实现对每次会话生成全新私钥，跨会话的标签不可关联，防止"重放旧标签做增量探测"。

## 6. 实现安全措施与部署建议

代码层面（已落实）：

- **素数阶群**：Ristretto255 消除了 Curve25519 的余因子/小子群与非法曲线点问题，所有点编码规范唯一；
- **常数时间运算**：标量乘使用 libsodium 的 `crypto_scalarmult_ristretto255`（常数时间），无私钥相关分支；
- **均匀哈希到曲线**：`ristretto255_from_hash`（Elligator 2），输出分布均匀，满足随机预言机建模；避免 try-and-increment 的时序泄露；
- **会话私钥**：每次协议会话由 `crypto_core_ristretto255_scalar_random`（OS CSPRNG）重新采样，进程内以 `sodium_memzero` 销毁；私钥永不出本行进程；
- **顺序打乱**：盲化点集在发送前做 Fisher–Yates 置换（CSPRNG 种子），对方无法把点关联回名单行号；
- **明文不出域**：名单明文只存在于本行进程内存；网络上传输的只有 32 字节曲线点；
- **一致性校验**：双方各自独立求交后比对交集计数，不一致即报错（能发现部分篡改/故障）。

部署建议（超出本演示范围）：

- 传输层启用 **TLS 双向认证**（防御主动中间人；被动窃听已由协议本身防御）；
- 恶意模型防护：若不能排除对方作恶，需为每次幂运算附加 **Chaum–Pedersen 离散对数相等性零知识证明**，或改用恶意安全的 PSI（如基于 OT 的 KKRT/PaXoS）；半诚实版本与恶意版本的通信量相同，主要代价是证明生成/验证的计算开销；
- 大交集场景下交集本身即敏感信息，导出文件应加密落盘并控制访问权限。

## 7. 性能（实测，Apple Silicon 14 核）

| 阶段 | 100 万条/方 |
|---|---|
| 本地盲化预处理（哈希到曲线 + 标量乘，每方） | ≈ 7 s |
| 协议三轮（含 32 MB×3 网络传输与二次盲化） | ≈ 6 s |
| 端到端（预处理 + 协议） | ≈ 13 s |
| 内存占用（每方） | ≈ 300 MB |

复杂度：计算 $O(n)$ 次标量乘（每方约 $2n$ 次），通信 $O(n)$ 个群元素（每条约 96 B 双向合计）。千万级名单线性扩展，预计 2 分钟内完成。
